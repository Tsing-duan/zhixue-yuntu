# 招聘 Demo 脚本（3 分钟）

目标不是浏览所有菜单，而是用一条纵向流程证明：三角色业务成立，AI 使用真实业务上下文，服务端授权与工程证据可复核。

## 录制前准备

- 使用专用 Demo 数据库，按顺序导入两份 SQL；确认 MySQL、Redis、后端和两套前端都已启动。
- 准备学生、教师、管理员三个隔离浏览器会话，并提前完成登录。不要在录屏中输入或展示账号凭据。
- 学生页预先打开 `/ai` 的“AI 错题 Agent”，教师页预先打开 `/aiData` 的自有课程，管理员页预先打开 `/aiData` 用量区。
- 优先复用数据库中已保存、且来自已验证真实调用的生成历史。需要现场调用时，先确认 Provider 可用和调用预算；不要为了等待动画让节奏失控。
- 将 README、架构图和下面四张脱敏证据图预先打开，但不要打开包含环境变量、请求头、登录响应或完整报告的窗口：

## Provider 延迟或失败预案

1. 现场调用超过约 8 秒仍未结束，就切到已保存历史或对应脱敏截图，不在 loading 页面停留。
2. 明确说“这是此前真实 Provider E2E 的保存结果”，不要说成这次录屏刚刚生成。
3. 若页面返回失败提示，只解释 fail-closed 行为：没有成功历史、没有成功 token 增量；不要临时重试并消耗额外预算。
4. 不打开 Network 请求头、环境配置、Redis token、数据库密码字段或 Provider 控制台。

## 不展示的内容

- 不输入或口述密码，不展示 API Key、JWT、请求头、`.env` 或终端环境变量。
- 不滚动长篇历史报告；证据只展示表格、聚焦行或脱敏截图。
- 不展示所有菜单，不展开文章/论坛等非核心模块，也不现场运行全量构建。
- 不把 fake server 测试说成真实 Provider 调用，不把两个真实入口扩写成六个都做过真实调用。
